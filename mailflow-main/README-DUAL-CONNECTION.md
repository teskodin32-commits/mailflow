# MailFlow — Google Sign-In + Email/App Password

This is the **integrated MailFlow source project** (not a standalone add-on).

## What changed?

- Google Sign-In (OAuth + Gmail API) is still available and uses the same routes. Its callback now checks an anti-forgery state generated by the original Google Sign-In action.
- "Email + App Password" connects Gmail accounts using Google SMTP on port 465.
- Both are displayed in **Gmail Accounts** and use the **same numeric account IDs**, campaigns, message queue, analytics and follow-up scheduler.
- Passwords are verified with Gmail first, encrypted with AES-256-GCM and never returned to the browser or included in an account export.
- PIN-protected account and campaign operations are now checked by the backend too. Existing PIN UI is retained.
- One email address may have **one** connection method at a time (because the original `accounts.email` database column is unique). To change the method for an address, remove it from the account list and reconnect with the other method. For different addresses, both methods can coexist indefinitely.

## Deploy in 5 steps

1. Back up your current MailFlow repository and Neon database before deployment.
2. On your backend host (Render/Railway or similar), configure these required environment variables:
   - `DATABASE_URL` — keep your existing value.
   - `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` — **keep** your existing values; Google OAuth is not replaced.
   - `APP_PIN` — your actual **four-digit** MailFlow dashboard PIN. **Required now**; there is no insecure default `1234`.
   - `SMTP_CREDENTIALS_KEY` — a **new, private 64-character hexadecimal encryption key**. Generate with:
     `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`
     Save the generated value in the backend's environment variables and keep a secure backup of it. **Never change or lose it** while SMTP accounts are connected, or their saved passwords become unreadable. Never put it in your frontend or GitHub.
3. Apply `migrations/001_dual_gmail_connections.sql` in the Neon SQL editor **before** deploying (the backend also performs this additive migration automatically). This leaves old Google accounts and campaign data intact.
4. Deploy the backend from this folder (`npm install`, then `npm start`). Deploy the `frontend` folder separately (`npm install`, then `npm run build`). Set `REACT_APP_API_URL` to your **actual backend base URL** in the frontend deployment settings. Do not paste real passwords or secrets into source code.
5. Open MailFlow → Gmail Accounts. Choose **Sign in with Google** (existing behavior) or **Email + App Password**. With an SMTP account, use **Verify** and **Send test** to check the connection (test sends only to that same account's inbox).

## Important limitations

- Google App Passwords require a Gmail/Google Workspace account with Google 2-Step Verification and an available App Password option. Visit https://myaccount.google.com/apppasswords. Use the **16-character App Password**, not the normal Gmail password.
- The backend **must support outbound SMTP to smtp.gmail.com:465**. Render's Free web service doesn't permit outbound SMTP; Google OAuth can still work there. Paid Render or another compatible host is necessary for the App Password method.
- App Password connections **cannot be restored from the exported accounts JSON** because encrypted secrets aren't exported; reconnect them manually after a database restore. OAuth backups still contain sensitive OAuth tokens; treat downloaded JSON backup files as secrets and don't share them publicly.
- This code has **offline syntax/unit tests** but is **not deployed or live tested** with your Gmail account, Neon database, or cloud host. To run the unit tests: `npm test`.
- Protect your API with secure credentials and use MailFlow only for legitimate, permission-based email. Gmail sending quotas still apply. App Password is an account connection option, not a way to increase Gmail quota.

## Files changed

- `db.js` and `migrations/001_dual_gmail_connections.sql`: additive account fields.
- `routes/smtp-accounts.js`: connect, verify and send test with App Password.
- `lib/gmail-smtp.js`, `lib/smtp-crypto.js`: Gmail SMTP sender and encryption.
- `scheduler.js`: automatically sends campaigns and follow-ups through the selected account's Google API or SMTP route.
- `frontend/src/pages/Accounts.js`, `frontend/src/api.js`, `frontend/src/App.js`: both UI choices, test buttons and authenticated requests.
- `routes/middleware/auth.js`, `routes/accounts.js`, other protected routes: backend PIN checks and secret-free SMTP account exports.
- `.env.example`, `package.json`: new configuration and dependencies.

The original Google API OAuth callback (`/api/accounts/callback`) stays reachable to Google without an `x-app-pin` header; the other account routes require the verified dashboard PIN.
